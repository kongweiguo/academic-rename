# 学术文献统一命名规范

这是 academic 系列技能唯一的书目命名规则。`academic-rename` 按本文件识别、规划、执行和恢复；翻译与精读仅在用户明确要求规范命名时读取，不复制规则。专业成果的用途后缀与内容结构由对应技能维护，不属于另一套书目命名规则。

- [命名与书目核验](#命名与书目核验)：身份、基本名、日期、CCF 及待核实状态。
- [执行与恢复](#执行与恢复)：范围、冲突、日志、安全改名与恢复。
- [与专业技能交接](#与专业技能交接)：输入、实际源状态、基本名和续跑兼容。

## 命名与书目核验

### 当前文献与对应学术成果

适用于会议论文、期刊论文、预印本、学位论文、报告、书籍、章节及补充材料，支持本地或已连接远程的 PDF、DOCX、HTML、Markdown、TXT、EPUB 等可读取文件和可编辑在线原生文档。缺少读取能力的类型列为不支持或待处理。

1. 为每个源对象建立独立、持久可复用的 `resource_id`。本地记录完整路径、父目录、真实扩展名、大小、可用文件系统身份及 SHA-256；远程记录平台、类型、原生稳定 ID/token、父级 ID、URL、实际名称、读写能力及可得版本/修订标识或正文快照，二进制另记真实扩展名和可得内容哈希。同字节副本仍需独立 ID，不能只以内容哈希识别每份文件。
2. 从封面、首页、版权页、出版声明和正文提取题名、署名与出版信息。PDF 双栏混排、扫描或乱码时渲染核对，必要时使用本地 OCR；其他格式读取题名页、正文和元数据，在线文档通过所属平台读取并核对原始附件。仅为大型学位论文改名不必处理全文。文件属性、旧文件名、页面标题和搜索摘要只作线索。
3. 区分单篇原文、预印本、投稿稿、作者录用稿、译文及补充材料。阅读笔记、合集和整册论文集不按第一篇引文或论文命名，保留原名并列为需要另定规则的对象。
4. 用 DOI、arXiv ID、ISBN、ISSN、题名及作者消歧。DOI 必须属于本篇，不能取自参考文献；`XXXXXXX`、`Conference acronym XX` 等模板占位值不是证据。
5. 公开材料查询出版社、会议论文集、ACL Anthology、期刊官网及标识符注册记录，并可用 DBLP、Crossref 交叉核对。题名与作者匹配不足时，不强行关联正式论文。
6. 未公开投稿稿或私人评审材料默认在本地识别，不向外部搜索或处理服务提交全文、摘要、评审意见或未公开题名。CCF 核验只需公开渠道名称；用户另行授权外部查询时按其范围执行。

日志分开保存两组信息：当前文献的实际完整题名、完整署名、文献类型、对象版本、版本日期及依据；对应学术成果的已核实正式题名、出版年月、实际渠道、DOI、录用或出版状态及关联证据。

标题缩写派生自当前文献真实题名。已可靠对应正式论文的预印本可采用正式成果的日期、渠道及等级排序，但保留 `Preprint-vN` 并说明字段来源。作者自述录用而缺少会议或出版方证据时只记录声明，不直接按正式录用判级。旧名中的 `v1`、`R1`、“终版”等线索注明出处；`Poster` 可能只是主会长文展示形式，须核实论文集类别；投稿系统文件名含 `Proof` 不能证明是出版校样。

### 六段基本名与标题缩写

本地文件、远程普通文件和在线原生文档共用不含扩展名的基本名 `N`：

```text
[YYYYMM][CCF等级][来源][标题缩写][作者][版本]
```

只缩写标题字段，完整保留日期、等级、渠道、作者和适用版本。各字段置于方括号；无适用版本的正式出版版可省略末段。用户指定字段顺序、作者格式、日期口径、完整题名或目录版次时优先采用，并记入计划。

例如以下仅演示格式，不能作为其他论文的元数据：

```text
[202605][CCF不适用][投稿-TMM][XXXX_YYY_Z][Weiguo Kong et al.][Submission-R1]
```

`XXXX_YYY_Z` 是缩写形状占位，不是真实题名。真实文件使用 `N` 加实际扩展名并保留扩展名大小写；在线原生文档直接用 `N`，不添加虚构扩展名。

| 字段或类型 | 规则 |
| --- | --- |
| 正式会议或期刊 | 使用已消歧的标准简称，例如 ACL、AAAI、TDSC、TCSVT、SIGPRO。 |
| 学位论文 | 渠道字段写学校，版本为“博士论文”或“硕士论文”；无学校依据时列“学校待核实”并记录缺失项。 |
| 无已核实正式发表关联的预印本 | 渠道写 arXiv 或核实的平台，保留 `Preprint-v1` 等当前版本。 |
| 投稿稿 | 渠道如 `投稿-TCSVT`，保留 `Submission-R1` 等；日期使用当前稿件提交日期。 |
| 报告、书籍和章节 | 渠道写机构、出版社或所属书名，保留文献类型及已知版次。 |
| 作者 | 中文按原文署名，如“张飞”“张飞等”；外文保留第一作者完整署名，多作者加 `et al.`。不猜姓氏、中文名或通讯作者；日志保存完整作者信息。 |
| 版本 | 预印本、作者录用稿、投稿稿、补充材料和译文须保留适用身份及已核实版本，不能为缩短名称而省略。源版本不替换为下游工作状态。 |

标题缩写优先用用户指定缩写，否则保留题名中真实存在的方法名或已有缩写，再选择可辨认主题的少量关键词、短语或首字母，以 `_` 连接。不把生成缩写称为论文官方方法名；不限定固定字数，以可识别、可复用且满足限制为准。计划和日志保存“完整题名 ↔ 缩写”映射、来源（用户指定/已有方法名/生成）及消歧信息，身份与设置未变时复用已核实映射。

完整题名、正文和信息卡不缩写。超长只精简标题字段，不能压缩作者全名、`et al.`、适用版本或扩展名。消歧片段和稳定短 ID 放在标题字段内部，如 `[Method_Topic_ab12cd34]`，不增加第七段。

### YYYYMM 日期

采用书目事件日期，不用下载、上传、创建、修改时间，也不用学号、稿件编号、模板或参考文献年份代替。

| 文献状态 | 日期口径 | 另行记录 |
| --- | --- | --- |
| 正式会议论文 | 对应届次年份及该届举办月份 | 论文集发布日期、跨年差异 |
| 已有卷期的期刊论文 | 正式卷期年份及月份 | online-first 日期、当前文件日期 |
| 仅有 online-first | 首次正式在线出版年月 | `year_basis=online_first` |
| 已录用未发表 | 有依据的录用年月，或明确会议届次及举办月份 | 保留 `Accepted`，不伪造卷期 |
| 无正式版本关联的预印本 | 当前版本提交年月 | 首发、修订日期及版本号 |
| 投稿修订稿 | 当前稿件提交年月 | 明确为提交时间，保留 `Submission` |
| 学位论文 | 授位年月；未载明则用明确完成年月 | `degree_awarded` 或 `completion` 依据 |
| 书籍或报告 | 当前版次出版或发布年月 | 版次、报告编号 |

年份为四位，月份补齐两位，二者属于同一事件；不得拼接卷期年份和 online-first 月份，或正式发表年份和投稿月份。已知年份但月份未知、多月合刊或区间无法唯一选月时写 `XX`，如 `[2026XX]`，记录原始区间及原因，此状态不阻止改名。年份也无依据时写 `[日期待核实]` 并列为待核实。日志保存完整已知日期、精度、年月分别采用的依据及输出标签。

### CCF 目录与待核实状态

默认使用执行时最新正式发布的《中国计算机学会推荐国际学术会议和期刊目录》，先查 [CCF 官方入口](https://www.ccf.org.cn/Academic_Evaluation/By_category/)。每批记录版次、正式发布时间、勘误日期、查询时间、来源链接及采用口径。用户指定版次时严格使用；要求“发表当时等级”时按目录实际发布时间与论文出版日期匹配，只有年份且恰逢切换无法确定时列为待核实。

可复用目录快照，但不能把公示稿、旧版或未经核验的快照称为最新。优先锁定一个版次的原始目录文件，避免与可能滞后的分类 HTML 混用。官方原文件不可读而采用高校等机构镜像时，保存官方发布说明、镜像来源、封面版次及文件哈希，不把镜像日期当正式发布日期。先按全称、学术系列、出版社、ISSN 或系列官网消歧，再使用简称；例如 Signal Processing 可用 SIGPRO，不能只凭 `SP` 匹配 IEEE Symposium on Security and Privacy。

| 标签 | 使用条件 |
| --- | --- |
| `CCF-A` / `CCF-B` / `CCF-C` | 正式发表或正式录用渠道、文献类型和目录均核实且精确命中；非出版版另保留当前版本。 |
| `CCF未收录` | 实际渠道明确，完整检查所选目录和别名后确认未收录。 |
| `CCF不适用` | 学位论文、书籍、报告、无已核实正式发表关联的预印本或投稿稿，或目录适用类型外的材料。 |
| `CCF待核实` | 来源、身份、适用类型或目录依据不足；无法访问目录不等于未收录。 |

已识别清楚的投稿稿可用 `CCF不适用` 与 `Submission`，不因尚未核实正式发表而阻塞，也不据此断言从未发表。拟投渠道等级只能单列为“目标渠道等级”。按所选目录范围区分 Full/Regular 正式长文与伴随 Workshop、Short、Demo、Technical Brief、Summary、Findings，后者不继承主会等级；名称含 Workshop 但被官方独立列入的会议按独立条目核查。期刊扩展版匹配期刊本身；其他学科也核查具体渠道，不凭学科名称判断。独立的 T1/T2/T3 科技期刊目录不与国际 A/B/C 换算。

历史检索入口：[第七版正式发布及勘误](https://www.ccf.org.cn/Academic_Evaluation/By_category/2026-03-31/870181.shtml)、[2022 版正式发布](https://www.ccf.org.cn/Academic_Evaluation/By_category/2023-03-08/787209.shtml)、[独立科技期刊目录](https://www.ccf.org.cn/ccftjgjxskwml/)。这些链接不代替执行时版次核验。等级只用于排序和识别，不评价单篇论文质量。

题名、作者或身份存在实质冲突，以及必要字段待核实时，保留候选和缺失依据，不自动采用猜测名称。只有用户明确接受具体未知字段后，才执行带该待核实标签的候选；未知月份和不适用等级本身无需确认。保留未解决条目的实际源名，继续其他可执行条目，不重新索取整批授权。专业技能可继续不依赖规范命名的已授权内容工作，但不能把候选名称当作已执行结果。

## 执行与恢复

### 任务范围与模式

只处理用户提供或明确选定的文件、目录及链接。要求整个文件夹时遍历指定范围并处理分页，子目录范围依用户要求；不沿符号链接、快捷方式或正文链接扩大范围。只读、同步引用或身份不明对象不作改名目标。本地和已连接服务器文件留在原父目录；平台资源保持稳定身份、正文、共享权限和位置，不配置新服务器连接。

| 模式或要求 | 行为 |
| --- | --- |
| `preview` | 用户要求预览、命名草稿或测试但不改名时，默认在回复中交付名称、依据与冲突，不写源、成果或日志。用户明确要求保存预览时才写入指定位置，并标记未执行；不进入改名的写前日志与执行步骤。 |
| `apply` | 用户明确要求改名或整理名称时，先形成可审阅计划并持久记录，再执行已授权且证据充分的条目。已有授权不重复询问；用户要求先确认时等待其对具体计划的确认。 |
| `restore` | 仅在用户要求撤销时，按已验证成功的日志恢复仍处于改名后状态的源对象。 |
| 仅规范新成果名称 | 核验并交付基本名和冲突计划，源名保持不变；创建成果由对应专业技能执行。 |
| 不改名或普通翻译/精读 | 不执行源改名，也不检索只服务于改名的字段；使用专业技能原名派生默认值。 |

只命名不创建译文、精读目录、图片目录或在线成果，也不询问专业成果平台。只有调用方已经提供衍生目标时，才把它们纳入命名约束。远程只有读取权或缺少原生改名接口时记录 `skipped_no_permission` / `skipped_unsupported`，保留实际源名；不更换身份、复制原文或下载重传绕过限制。

### 名称与位置冲突

1. 使用 Unicode NFC，清理重复空格与非语义断行；完整题名另存，记录与官方题名差异。本地和普通远程文件的 `:`、`/`、反斜杠替换为 ` - `，`? * " < > |` 使用无歧义的可显示替代字符；移除控制字符、路径分隔作用、末尾空格和句点，避开 Windows 保留名。原生标题按接口限制清理；字段内方括号转义为全角括号等，不丢失字段语义。
2. 本地默认每个 basename 不超过 240 个 UTF-8 字节，并核实实际文件系统与完整路径限制。源文件为真实扩展名留预算；调用方给出衍生产物时，以全部计划结果的最大后缀统一预算。例如 `_翻译.md` 和 `_精读.md` 各占 10 个 UTF-8 字节；不能只检查源文件。远程文件核实服务端限制，原生文档核实标题限制及计数单位，不能用汉字数替代字节数。
3. 超限只精简标题缩写，按完整词语或 Unicode 字符边界截取，预留标题内消歧预算。其他身份字段本身已超限，或用户要求保留的完整题名容不下时列为待处理，说明限制；不截掉作者、版本，也不单独缩短衍生成果破坏统一基本名。
4. 检查同父级现有名称、本批计划名称及调用方提供的全部派生路径。本地和普通远程文件采用大小写折叠及 Unicode 规范化作保守碰撞检测；在线即使允许同名也检查已知同级对象。查询不足时记录检查范围，不声称排除全部冲突。同名目标不覆盖、不删除。
5. 先以已核实版本区分；仍冲突时在标题缩写内加入 DOI/arXiv ID 的可辨认片段，再尝试持久化独立 `resource_id` 的稳定短哈希，依次为 8 位、12 位和长度允许的完整 ID。仍被占用或无法容纳则列冲突，不增加第七段，不无限加序号或每次变化的随机数。同字节副本使用独立 ID。
6. 已有专业成果的同名或论文题名不能证明其归属。由对应技能核对源 ID、源哈希、成果路径/原生 ID、实际创建记录及可得修订或内容快照；只有计划不证明已创建。归属不明、日志损坏或内容不符时保持现状，解决整体基本名冲突或列为冲突，不覆盖用户修改。
7. 续跑先读取可验证日志，复用 ID、缩写映射和已核实位置。源名已符合时标记“无需修改”，不叠加标签或重分配 ID。同一论文不同版本、补充材料和译文保持独立对象；技能拆分本身不是重命名已有成果的理由。

### 计划、写前日志与兼容

计划至少列出目的、模式、原名/新名、完整题名/缩写、实际来源、年月及依据、CCF 等级/目录口径、当前版本、关键证据、源路径或稳定 ID、本地日志位置、置信状态与冲突/待核实原因。置信状态用“可执行 / 待核实 / 无需修改 / 不支持”，不用平均分数掩盖关键身份冲突；调用方给出派生产物时另列其位置、后缀和命名范围。

日志采用可扩展的 `schema_version: 2`，保存 `batch_id`、`task`、`mode`、`settings` 及 `entries`，以 UTF-8 JSON 持久保存并回读。示意字段不代表已经取得证据。

| 字段组 | 必存内容 |
| --- | --- |
| 源身份与名称 | `resource_id`、`source_type`、`original_name`、`planned_name`、实际回读后的 `verified_name`、`source_location`、`snapshot_before` / `snapshot_after`。 |
| 书目依据 | `current_document`、`related_publication`、`date`、`ccf`、`evidence`、识别时间、完整作者及题名、日期精度及年月依据、实际/目标渠道、版本和目录来源。 |
| 缩写映射 | `title_abbreviation` 的 `full_title`、`abbreviation`、`basis`、`disambiguation`。 |
| 执行事实 | `confidence_status`、`rename_status`、逐步 `events`、时间、结果与原因；按实际记录 `planned`、`renamed`、`verified`、`failed`、`skipped` 等。 |
| 本地证据 | `original_path`、`renamed_path`、原父目录、大小、可用文件系统身份、`sha256_before` / `sha256_after`。 |
| 远程证据 | 平台、资源类型、原生 ID/token、父级 ID、URL、权限及可得版本/修订、内容哈希或正文快照；普通服务器文件另存新旧路径，Wiki 区分节点 token 与正文 token。 |
| 可选交接信息 | 调用技能、规范命名范围、基本名、衍生后缀与目标位置、旧日志中已存在的专业成果关联；只保存已知事实，计划目标不记为已创建。 |

日志保存在任务工作区或用户指定可写本地位置，不自动上传文献目录或写入源正文，不为日志创建译文或精读目录。无持久记录能力时不执行改名或恢复。批量任务各条保留独立身份与结果；不能把一条的唯一恢复记录藏在另一条无关联的成果中。

兼容原 `academic-rename` 及合并版 `academic-translate` 已留下的可验证日志，包括 `schema_version: 2`、`task: translation`、旧 `rename-log.json` 和未归档的 `.academic-translate-*.rename-log.json`。保留原 `resource_id`、缩写映射、成功事件、源路径和已有成果字段；只补充能核实的缺失信息，不为了新字段重做已成功操作、不改写历史事实。没有版本号的旧日志按现存证据核对，缺关键恢复依据时保留现状并报告。

旧日志中的 `output_dir`、`markdown_path`、`images_dir`、译文 ID 等由专业技能解释和续跑。本技能不迁移旧成果或擅自搬移日志；专业技能可继续引用既有日志位置。普通翻译/精读没有改名日志或没有 `rename_status=verified` 并不构成失败，其来源与进度由各自状态记录维护。

### 本地改名

下列变更只用于已授权 `apply`；`preview` 按模式表交付未执行计划，不执行以下写入步骤。

1. 核实身份、元数据与全部已知目标路径；先排他创建批次日志并回读，日志失败时不改名。已有日志在核对身份后续记，不覆盖不相关日志。
2. 写入前重新核对路径、独立身份、SHA-256、权限和目标占用；源在计划后变化时跳过，不按旧快照执行。
3. 使用明确不会覆盖目标的操作，不能把普通 `rename` / `mv` 默认行为视为不覆盖保证。大小写改名或名称互换需要中转时，先检查并持久记录唯一临时路径，每步更新事件和实际路径。
4. 从新路径回读，确认仍在原父目录、SHA-256 相同，正文与阅读批注字节均未改变。失败时停止该项后续写入并保留日志；结果未查明前不交出计划路径冒充真实路径。

### 远程改名

使用当前已连接且授权可用的等价工具，不假设固定命令已安装，不新增服务依赖：

- 服务器普通文件用授权接口按原目录和稳定身份改名，前后核对内容哈希与父目录；无法保证不覆盖或核实身份时报告能力限制。
- Lark / Feishu 按 URL 路径和类型选择当前文件、文档或知识库能力并读取工具说明。宿主已提供相关技能时按需读取；文件夹用清单接口并处理分页，上传文件用下载/预览，原生正文用对应读取能力。Wiki 节点标题使用节点 token，不能将底层正文 token 当节点标题目标。批量改名串行执行。
- Notion 等原生文档用稳定页面/资源 ID 核实编辑能力，只更新名称/标题字段，不替换正文；字段位置以平台实际结构为准。
- 普通论文网页、arXiv 和出版社页面可读不代表可改其标题。只在用户已授权下载副本或新成果命名时对该目标规划，不擅自新建原文副本。

已授权 `apply` 的每个条目顺序执行；`preview` 只读取必要信息并按模式表交付，不进入以下写入步骤：

1. 在本地持久保存源 ID、原名/计划名、父级、内容/版本快照、权限与冲突结果；日志失败时不写远端。
2. 更新前重新读取同一 ID，核对名称、父级、类型、正文/版本、权限和占用。用户在计划后修改时跳过；平台支持条件更新时使用修订约束。
3. 原生更新名称/标题，保留稳定 ID、父级和资源，记录结果。不移动、删除、更换身份或下载重传。
4. 按同一 ID 或核实的新路径回读实际名称、身份、父级和正文。二进制用可得哈希，原生正文用内容快照等；标题更新引起的修改时间变化不等于正文变化。只能回读标题时如实说明范围，不声称已验证字节。
5. 持久保存实际结果，再交回专业技能。权限或能力受限时交回实际未变名称；结果未知先查明，不以计划名给原始附件或源引用命名。

### 重试与部分完成

暂时限流或网络错误最多重试 3 次；超时或结果不明先回读资源及日志，再判断是否重试。权限不足、资源不存在或类型不支持时说明原因，不换身份绕过。逐项记录成功、失败和未执行，不声称整批原子成功；续跑核验成功条目，不重复改名。

### 恢复

仅使用已验证成功的日志，不解析新名猜原名。先记录恢复计划：本地和普通服务器文件核对当前新路径、独立身份、改名后哈希及原名占用，再不覆盖地恢复，验证哈希和父目录；原生文档核对 ID、当前名、父级、内容/修订及权限，用同一标题接口恢复并回读。后续内容修改、路径/父级变化、名称占用或证据不足时保留现状并报告冲突。

恢复只改变日志范围内的源名称，不删除、移动或改名译文、精读目录、图片、在线成果及其内容。记录恢复后的实际源名、路径/ID、日志事件及已知关联成果，将可能失效的源引用交给对应专业技能处理。引用修复需由该技能核实归属和后续修改状态，并在用户任务范围内执行；不能安全修复时报告当前源路径/URL和受影响引用，不覆盖用户编辑。

交付逐项实际结果、新旧名称、未执行原因、采用的目录口径、可恢复日志位置以及交接信息。未发生写入时明确为预览，不把计划当作成功结果。

## 与专业技能交接

普通翻译和精读不需要本技能。用户明确要求规范源名或新成果名称时，调用方说明命名对象与授权范围，提供源实际名称、路径/稳定 ID、已有状态或日志位置，以及新成果的用途后缀、真实扩展名、目标父级和已知占用情况。只要求规范成果名不授权改源名；用户同时要求先改名再翻译或精读时，完成获授权的源改名再交回。

本技能按同一规则生成基本名，统一考虑调用方提供的长度与冲突约束。交回以下结果：实际源名称与实际路径/URL、稳定 ID、源哈希或可得修订、已核验基本名及适用范围、拟定与实际执行状态、日志位置、未解决字段或冲突。计划名与回读后的实际名明确区分；只规范成果或源改名受限时二者可以不同。

调用方取得结果后自行创建专业成果、保存进度及来源关联，不重新推导书目字段或再造缩写。命名记录不可得时不能靠文件名反推完整书目信息。显式规范命名受阻不妨碍不依赖该步骤的已授权内容工作，但不得将候选名、跳过项或未完成命名说成已完成。

续跑优先采用旧日志或专业状态中已核实的源与成果对应关系，保留既有路径/在线 ID 和用户修改；不因普通任务的新原名派生默认值重建第二份成果。只有用户要求调整既有名称时才另行规划命名。源恢复后的链接与专业状态修复由对应技能负责，命名技能只交接实际变更。
